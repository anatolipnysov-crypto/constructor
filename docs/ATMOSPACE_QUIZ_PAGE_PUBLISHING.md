# Публикация квиз-страниц Atmospace

## Результат

Конструктор получает безопасную основу автоматической публикации готового квиза:

```text
подготовленный квиз
→ адрес страницы
→ публикация
→ публичная ссылка /q/<адрес>
```

Скачивание HTML-файла сохраняется как запасной вариант.

## Что уже реализовано в коде

- защищённый серверный маршрут публикации;
- хранение готовых страниц в Cloudflare KV;
- публичная раздача страницы по адресу `/q/<slug>`;
- проверка структуры готового квиза перед сохранением;
- ограничение размера запроса и HTML;
- версия содержимого по SHA-256;
- ETag и безопасное кеширование;
- базовые security headers и Content Security Policy;
- человеческие ошибки в интерфейсе;
- проверка, что возвращённая ссылка принадлежит текущему домену конструктора;
- сохранение последней опубликованной ссылки без защищённых данных.

## Безопасное состояние по умолчанию

Автоматическая публикация выключена, пока одновременно не выполнены все условия:

1. создано Cloudflare KV-хранилище;
2. KV привязано к Pages-проекту как `ATMOSPACE_QUIZ_PAGES`;
3. конструктор и маршрут публикации защищены Cloudflare Access;
4. публичный маршрут `/q/*` исключён из обязательной авторизации;
5. задан режим `ATMOSPACE_QUIZ_PUBLISHING_MODE=cloudflare_access`;
6. Pages-проект пересобран после изменения привязок и настроек.

Без включённого режима сервер отвечает человеческим сообщением и предлагает скачать страницу файлом.

## Граница Cloudflare Access

Проверка Access-заголовков в функции является дополнительной защитой, но не заменяет реальную Access-политику на стороне Cloudflare.

Правильная схема:

```text
конструктор и /api/quiz/publish
→ доступны только разрешённым операторам

/q/*
→ публичные рекламные страницы
```

Нельзя включать `ATMOSPACE_QUIZ_PUBLISHING_MODE=cloudflare_access`, пока Cloudflare Access фактически не защищает интерфейс конструктора и серверный маршрут публикации.

## Защищённые данные

В опубликованную страницу и ответ публикации не попадают:

- разрешение Метрики;
- CAPTCHA-ключи;
- пароли;
- Access assertion;
- email оператора;
- API-токены;
- серверные ключи Atmospace.

Готовая страница содержит только публичную конфигурацию квиза, номер счётчика, безопасный ключ лендинга и браузерную логику атрибуции.

## Ограничение первой версии

Первая версия публикует страницы на том же домене, где работает Cloudflare Pages-проект конструктора:

```text
https://<домен-конструктора>/q/<адрес>
```

Публикация на произвольные клиентские домены, автоматическое управление DNS и Cloudflare Custom Hostnames в эту задачу не входят.

## Проверка после будущего включения

1. Оператор входит в защищённый конструктор.
2. Подготавливает квиз и связь с Atmospace/Метрикой.
3. Указывает адрес страницы.
4. Нажимает «Опубликовать».
5. Получает HTTPS-ссылку `/q/<адрес>`.
6. Публичная ссылка открывается без входа в конструктор.
7. Обновление той же страницы меняет версию и ETag.
8. `yclid` и UTM сохраняются при открытии страницы.
9. Онлайн-цели проходят в выбранный счётчик.
10. Кнопка регистрации получает адрес только от Atmospace API.

## Production boundary

Следующие действия требуют отдельного явного CHECKPOINT:

- создание KV namespace;
- изменение Cloudflare Pages bindings;
- создание или изменение Cloudflare Access application/policies;
- добавление переменной режима;
- изменение домена;
- production redeploy;
- публикация первой боевой страницы.

## Safety

- no secrets or environment values are committed;
- no existing design replacement;
- no lockfile or GitHub workflow change;
- no production setting or deployment;
- no DNS, VPS, Supabase, Netlify, or Atmospace production change.

## UI acceptance

No internal technical copy is visible in user-facing UI. All visible text must be product/human copy, not developer/debug/system wording.
