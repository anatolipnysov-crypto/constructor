# Защищённое хранение данных проекта

## Проблема

Старый конструктор сохраняет рабочую панель в `localStorage` под ключом `constructorProjectData`.

В состав старой панели входит поле разрешения Метрики. Поэтому ранее защищённое значение могло попасть в долговременное браузерное хранилище вместе с обычными ссылками проекта.

## Результат

Перед первым отображением конструктора устанавливается узкая защитная граница:

```text
старые данные проекта прочитаны
→ защищённые поля удалены
→ безопасные поля сохранены
→ все дальнейшие записи автоматически очищаются
```

## Что удаляется

Удаляются поля, название которых указывает на защищённое значение:

- token;
- password;
- secret;
- credential;
- captcha;
- API key;
- authorization;
- старое поле `metrikaToken`;
- поля разрешения отправки рекламных результатов.

Проверка выполняется рекурсивно, включая вложенные объекты и массивы.

## Что сохраняется

Обычные рабочие данные продолжают сохраняться:

- название проекта;
- домены и ссылки;
- номер счётчика;
- тексты;
- настройки конструктора;
- другие значения, не являющиеся секретами.

## Границы

- защищённое значение может существовать в памяти текущей вкладки, пока оператор работает с ним;
- после записи проекта оно не попадает в `localStorage`;
- после перезагрузки старое значение не восстанавливается;
- защита действует только для `constructorProjectData` в `localStorage`;
- другие ключи и `sessionStorage` не изменяются;
- никаких значений не отправляется на сервер.

## Следующий продуктовый шаг

Старое поле разрешения Метрики следует позднее удалить из legacy-панели или заменить отдельным одноразовым действием. Для этого потребуется аккуратная декомпозиция большого `src/App.jsx`. Текущая защита уже закрывает долговременное хранение без рискованной переработки этого файла.

## UI acceptance

No internal technical copy is visible in user-facing UI. All visible text must be product/human copy, not developer/debug/system wording.
