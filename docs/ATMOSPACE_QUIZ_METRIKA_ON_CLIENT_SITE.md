# Метрика на сайте клиента

## Продуктовая схема

Клиент размещает готовый код квиза на своём домене и подключает свой счётчик Метрики средствами Tilda или другого сайта.

```text
счётчик подключён в настройках сайта клиента
→ готовый код квиза использует номер этого счётчика
→ landing_view и прохождение квиза отправляются онлайн
→ регистрация, уведомления и оплата отправляются сервером Atmospace
```

## Что делает код квиза

Код квиза:

- не загружает библиотеку Метрики второй раз;
- не вызывает повторную инициализацию счётчика;
- не создаёт дополнительный просмотр страницы;
- отправляет только цели квиза через `reachGoal`;
- ждёт загрузки счётчика при отложенной аналитике;
- не мешает переходу к регистрации, если Метрика временно недоступна.

## Что делает клиент

Для Tilda клиент:

1. подключает номер счётчика в настройках сайта;
2. сохраняет изменения;
3. публикует страницы сайта;
4. вставляет готовый код квиза в блок T123;
5. проверяет цели на опубликованной странице.

Для другого хостинга счётчик устанавливается штатным способом этого сайта до запуска рекламы.

## Разделение целей

Онлайн на домене клиента:

- `landing_view`;
- `quiz_question_1_answered` — `quiz_question_7_answered`;
- `quiz_completed`;
- `registration_click`.

Сервером Atmospace:

- `registration_success`;
- `notifications_connected`;
- `payment_success`.

## Безопасность

Разрешение Метрики используется только во время подготовки целей и не попадает в готовый код. Партнёрский код также не экспортируется в клиентскую страницу.

## UI acceptance

No internal technical copy is visible in user-facing UI. All visible text must be product/human copy, not developer/debug/system wording.
